# Hundred Items, Part 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the item system of `docs/superpowers/specs/2026-11-05-hundred-items-design.md` (build-order steps 1 and 2): effect hooks, rarity, curses, tags, unlock sources, combos, and the 20 reworked items, so later batches can add the 80 new items quickly.

**Architecture:** An item keeps its `StatEffect` numbers for anything always on, and may carry an `ItemEffect` sub-resource whose hooks run at moments of play. `RunEffects` (owned by `RunState`) keeps one duplicated effect per held item and per formed combo, in pickup order, and is the only thing game code calls. `EffectContext` is the effects' only window on the scene. Rarity, sources and unlocks are pure static rules in core classes, so tests reach them without scenes.

**Tech Stack:** Godot 4.7.2, GDScript, the project's own `tests/run_tests.gd` runner.

## Global Constraints

- No other game's name appears in any file, comment, asset name or commit message.
- No new dependencies.
- Old saves load. An item id a save knows keeps working; reworked items keep their id and file.
- Item texts: one short effect sentence, then one joke sentence. A cursed item says its drawback.
- Keep the project runnable after every commit, and keep `LESSONS.md` up to date.
- Files keep CRLF line endings. Never PowerShell Set-Content/Out-File on game files.
- RefCounted helpers: never close a reference cycle (RunState -> RunEffects -> EffectContext holds the run by WeakRef); connect signals to callables of objects that outlive them.
- Anything an effect leaves lying in a room must answer `RoomView.is_passing_effect` (ItemFx nodes do, through `ItemFx.is_passing_effect`).

**Interfaces:**
- `RunEffects.land(enemy, amount, source, push := Vector2.ZERO, to_attacker: Variant = null) -> bool` applies `hit_damage`, sets `enemy.harmless_death` from `stats.clean_kills`, uses `take_strike` when `to_attacker` is a Vector2 else `take_damage`, then fires `hit` and, on a death it caused, `kill`. - `CombatFeedback.slow_time(scale, real_seconds)`, `CombatFeedback.play(name)`.
- Room pickups: coins call `pickup("pension", amount)`; heals `pickup("heal", HEAL_AMOUNT)` and are takeable when `accepts_pickup("heal")`; Slips and Thermoses `pickup("slip"/"thermos", 1)`. `_create_shop` calls `shop_open(stock)`. `_finish_room` calls `room_clear(self)` for rooms that had enemies.
- FloorScene builds the context, sets `ctx.room` on every room entered, calls `room_enter`, `floor_start` on each path and landing (after the landing heal).

## How to add an item (for the batch agents)

1. **Data.** Copy any `data/items/*.tres`. Set `id` (never rename a shipped one), `display_name`, `description` (one effect sentence, one joke; a cursed item names its drawback), `rarity` (`common`, `rare`, `legendary`), `cursed`, `tags` (from `cane bite dodge defence money thermos vision room boss`), and **exactly one** source: nothing (open from the start), `craft_price > 0` (recipe), `from_bounty = true` (and point one poster's `extra_kind = "item"`, `extra_id` at it, moving that poster's cosmetic to the Decor Office), or `first_clear_path = "<path id>"`. `test_item_unlocks` fails if an item claims two.
2. **Always-on numbers** go in StatEffect fields (add a field to `stat_effect.gd` and fold it in `PlayerStats.compute` if none fits). Prefer a stat to an effect whenever nothing happens at a moment.
3. **Moments** go in an effect script `scripts/items/<id>.gd` that `extends ItemEffect` and overrides only the hooks it needs. Add it to the .tres as a sub-resource:
   ```
   [ext_resource type="Script" path="res://scripts/items/<id>.gd" id="2"]
   [sub_resource type="Resource" id="Effect"]
   script = ExtResource("2")
   [resource]
   ...
   effect = SubResource("Effect")
   ```
   and bump `load_steps`. Each run gets its own copy, so counters are plain member variables. Reset per-room counters in `on_room_enter`, per-floor ones in `on_floor_start`.
4. **Reach the game only through `ctx`** (`EffectContext`): `ctx.run()`, `ctx.player`, `ctx.room`, `ctx.notice()`, `ctx.heal()`, `ctx.pay()`, `ctx.spend()`, `ctx.enemies()`, `ctx.enemies_near()`, `ctx.hit_enemy()` (hits with source `item`, which fires the hooks again only one level deep), `ctx.stun()`, `ctx.drop()`, `ctx.add_fx()`, `ctx.slow_time()`, `ctx.play_sound()`. Every member may be null in tests, so check `ctx.player != null` before using a node.
5. **Visuals** come from `ItemFx` (shockwave, cloud, puddle, sparks, pop, blast). A new lingering node class must join `ItemFx.GROUP` or answer `RoomView.is_passing_effect`.
6. **Combos.** When both items of a spec combo exist, add `data/combos/<id>.tres` (a `ComboDef` with `item_a`, `item_b`, `display_name`, its stats and/or `effect`). The banner and the big map's list come for free.
7. **Coach.** Add a line to `CoachTips.TIPS`; the test wants one for every item.
8. **Test.** Add one `test_<id>_<rule>` to the batch's test file using `tests/support/item_kit.gd`:
   ```
   var kit := ItemKit.new()
   var run := kit.run_with("bingo_card")      # a RunState holding the real item
   for i in 4: run.effects.pickup(RunEffects.PENSION, 2)
   assert_eq(run.effects.pickup(RunEffects.PENSION, 2), 10)
   assert_eq(kit.pops.size(), 1)               # the kit records notices, pays, spends, fx and sounds
   ```
9. **Run** `--headless --path . --import` once after new class_names, then `tools/test.ps1`, and a full loop per batch.

The 12 spec combos all need at least one new item, so `data/combos/` ships empty here; the batch that adds the second item of a pair adds its combo.
